# Aegis Banking Engine

A Python banking engine designed to model reliable account operations, payment processing, transaction recording, and double-entry ledger behaviour.

Aegis is being developed as a software engineering portfolio project, with an emphasis on clean object-oriented design, financial correctness, validation, and automated testing.

> **Current status:** Active development — core banking and transaction functionality implemented with 37 automated tests passing.

## Features

### Account Management
- Create accounts with an owner, account number, and balance
- Deposit funds into an account
- Withdraw funds while preventing insufficient-balance transactions
- Validate monetary amounts before modifying account balances
- Use `Decimal` for monetary values to avoid floating-point precision issues

### Payment Processing
- Transfer funds between accounts
- Validate transfer amounts before processing
- Prevent transfers when the source account has insufficient funds
- Update source and destination balances following successful transfers
- Ensure failed transfers do not create transaction or ledger records

### Transaction Tracking
- Create a transaction record for successful transfers
- Generate a unique UUID for each transaction
- Record transaction timestamps in UTC
- Store transactions through a transaction repository
- Retrieve transaction history associated with an account

### Double-Entry Ledger
- Record ledger entries following successful transfers
- Create corresponding debit and credit entries for transferred funds
- Associate ledger entries with the relevant transaction and account
- Prevent ledger entries from being created for failed transfers

## How It Works

Aegis separates banking operations into distinct components so that account behaviour, payment processing, transaction recording, and ledger storage remain independent and testable.

A successful transfer follows this general flow:

1. A transfer request is passed to `PaymentService`.
2. The transfer amount is validated.
3. Funds are withdrawn from the source account.
4. Funds are deposited into the destination account.
5. A `Transaction` is created to record the transfer.
6. The transaction is stored in `TransactionRepository`.
7. Corresponding ledger entries are created for the source and destination accounts.
8. The ledger entries are stored in `LedgerRepository`.
9. The completed transaction is returned.

If validation fails, the transfer is rejected and no transaction or ledger entries are stored.

### Core Components

**`Account`**  
Represents a bank account and manages balance operations such as deposits and withdrawals.

**`PaymentService`**  
Coordinates transfers between accounts, including validation, balance updates, transaction recording, and ledger creation.

**`Transaction`**  
Represents a successful transfer between two accounts and records information such as the transferred amount, unique transaction ID, and timestamp.

**`TransactionRepository`**  
Stores successful transactions in memory and allows transactions associated with an account to be retrieved.

**`LedgerEntry`**  
Represents one side of the accounting record generated by a successful transaction.

**`LedgerRepository`**  
Stores the ledger entries generated by successful transfers.

### Double-Entry Ledger

Aegis records two corresponding ledger entries for every successful transfer: one for the source account and one for the destination account.

For example, a £100 transfer from Account A to Account B produces:

- Account A: `-100.00`
- Account B: `+100.00`

Both entries are associated with the same transaction, providing a consistent record of how funds moved between accounts.
